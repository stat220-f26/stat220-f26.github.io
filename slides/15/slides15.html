What you built

A language model

A language model assigns a probability to the next token, given the text so far.

  1. Split text into tokens (here: words)
  2. Count which tokens follow which
  3. Turn counts into probabilities
  4. Sample the next token, and repeat

From counts to probabilities

Sampling the next word

bigram_probs |>
  filter(word1 == "great") |>
  slice_sample(n = 1, weight_by = prob) |>
  pull(word2)
[1] "course"
bigram_probs |>
  filter(word1 == "great") |>
  slice_sample(n = 1, weight_by = prob) |>
  pull(word2)
[1] "passion"

Always picking the most likely word gives the same boring text every time. Sampling gives different text each run, with likely words chosen more often.

Where it breaks

Problem 1: one word of context

Each new word only “sees” the word right before it, so sentences wander.

[1] "great points discussed in an excellent course for those academic publishing the right was ok swirl"

→ Nothing connects the beginning of a sentence to its end.

Problem 2: words it has never seen

generate_text("llm", n_words = 10)
[1] "llm"

→ If a word never appeared in the training reviews, the model has nothing to say.

Problem 3: no notion of meaning

To the model, great and excellent are just two unrelated rows in a table. What it learns about one tells it nothing about the other.

# A tibble: 6 × 3
  word1     `times seen` `different next words`
  <chr>            <int>                  <int>

2 excellent         2654                    396
3 awesome            749                    186
4 fantastic          440                    119

→ Words that mean almost the same thing end up with very different amounts of data.

Problem 4: more context means less data

model different combinations seen only once
Bigrams (1 word of context) 180,469 72%
Trigrams (2 words of context) 396,151 86%

→ Looking at more words makes the model smarter, but most combinations are then ones it has barely seen.

What LLMs change

Fix 1: tokens are pieces of words

LLMs usually split text into subword tokens, not words. Rare and new words are built from familiar pieces.

unbelievably helpful instructors

un | believ | ably |  help | ful |  instruct | ors

Illustrative only. Real tokenizers split text differently.

Fix 2: meaning as numbers

Each token is represented by a list of numbers (an embedding) so that tokens used in similar contexts get similar numbers.

→ This lets a model handle contexts it has never seen exactly.

Fix 3: attention

Instead of one previous word, the model looks at all of the text so far and learns which earlier words matter most for the next one.

This idea, plus a very large neural network, is what a transformer is.

Training at scale

Same task as your bigram model: predict the next token.

  1. Pretraining: predict the next token over a huge amount of text, with an enormous number of adjustable numbers
  2. Fine-tuning: further training, including human feedback, so the model follows instructions and is helpful

Temperature

Temperature controls how much the model favors the top choices when it samples. High temperature = more randomness

Takeaways

Three things to remember

  1. An LLM is the same idea you built: predict the next token, then sample. What changes is how much context it uses and how words are represented.
  2. It predicts plausible text, not true text, so a fluent answer can be wrong.
  3. Its outputs reflect its training data (Step 6 of the activity).
