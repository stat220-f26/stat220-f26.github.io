Our question

How many people work from home, and where?

The American Community Survey (ACS) asks workers how they get to work. We’ll use table B08301, Means of transportation to work:

  • B08301_001: total workers (16 and over)
  • B08301_021: worked from home

The share working from home is B08301_021 / B08301_001.

Setup: store your API key (once)

WarningDo this in the Console, not in your .qmd

Run the code below in the Console. Don’t save your key in a chunk in this document, and never commit it to GitHub. Anything you push can be seen by anyone with access to your repo, and git remembers it forever.

  1. Paste your Census API key into this command (in the Console), and run it:
census_api_key("PASTE-YOUR-KEY-HERE", install = TRUE)
  1. Restart R (Session > Restart R).
  2. Check that R can see your key without printing it. This should say TRUE. (If you want to see your key, run Sys.getenv("CENSUS_AP?I_KEY") in the console)
nchar(Sys.getenv("CENSUS_API_KEY")) == 40

Your key now lives in a file called .Renviron in your home folder, not in your repo. You never type it into a document again.

Part 1: tidycensus

Get the data

wfh_mn <- get_acs(
  geography = "county",
  state = "MN",
  variables = "B08301_021",
  summary_var = "B08301_001",
  year = 2024,
  survey = "acs5",
  geometry = TRUE
)

Take a look at wfh_mn:

  • estimate is the number of people who work from home, and moe is the margin of error on that estimate
  • summary_est is the total number of workers

Map the share working from home

wfh_mn |>
  mutate(pct_wfh = estimate / summary_est) |>
  ggplot(aes(fill = pct_wfh)) +
  geom_sf() +
  scale_fill_viridis_c(labels = scales::label_percent()) +
  labs(fill = "Work from home") +
  theme_void()

Which counties have the highest share? Which have the lowest? Why might that be?

How do we find the variable IDs?

There are thousands of IDs. Search the variable labels with load_variables():

acs_vars <- load_variables(2024, "acs5", cache = TRUE)

acs_vars |>
  filter(str_detect(label, "Worked from home"), !str_detect(name, "PR")) |>
  select(name, concept, label)

The same label shows up in several tables. The concept column tells you which one you want.

Part 2: What is get_acs() doing under the hood?

Add show_call = TRUE to any get_acs() call and it prints the URL it is requesting. (Don’t leave this in a document you knit and push: see the warning below.) Here’s what a request like ours looks like:

https://api.census.gov/data/2024/acs/acs5?get=NAME,B08301_001E,B08301_021E&for=county:*&in=state:27&key=YOUR_KEY
Piece Meaning
https://api.census.gov/data The host
/2024 The year
/acs/acs5 The dataset (the 5-year ACS)
?get= The variables: NAME, B08301_001E (all workers), B08301_021E (worked from home)
&for= The geography: county:* means “all counties”
&in= …in this state: state:27 (27 is Minnesota’s FIPS code)
&key= Who you are

E means estimate and M means margin of error. (Add B08301_021M to get= to ask for it.)

Try it in your browser

Paste the URL above into your browser, replacing YOUR_KEY with your key. You should see rows of JSON: a list of lists, with the first row giving the column names.

Part 3: Talking to the API directly with httr2

Step 1: build the request

wfh_request <- request("https://api.census.gov/data") |>
  req_url_path_append("2024") |>
  req_url_path_append("acs") |>
  req_url_path_append("acs5") |>
  req_url_query(
    get = c("NAME", "B08301_001E", "B08301_001M", "B08301_021E", "B08301_021M"),
    `for` = I("county:*"),
    `in` = I("state:27"),
    key = Sys.getenv("CENSUS_API_KEY"),
    .multi = "comma"
  )

What are those arguments?

  • request() sets the host name, and req_url_path_append() adds the year and the dataset
  • req_url_query() adds the ?get=...&for=...&in=... part
    • .multi = "comma" joins several values with commas
    • I("county:*") means “leave this exactly as is” (don’t escape the : and *)
    • `for` and `in` need backticks because they are reserved words in R
  • Sys.getenv("CENSUS_API_KEY") reads your key from .Renviron, so it never appears in your document

Step 2: send it

wfh_response <- req_perform(wfh_request)

If it worked, wfh_response says Status: 200 OK. (404 means not found and 429 means too many requests. If you forget the key, you’ll get a “Missing Key” web page instead of data.)

Step 3: get a tibble

raw <- resp_body_json(wfh_response, simplifyVector = TRUE)
class(raw)
head(raw, 3)

The first row is the column names. Move it into the header, then make the numbers numeric:

colnames(raw) <- raw[1, ]

wfh_raw <- as_tibble(raw[-1, ]) |>
  mutate(across(starts_with("B08301"), as.numeric),
         pct_wfh = B08301_021E / B08301_001E)

wfh_raw |> select(NAME, B08301_021E, B08301_001E, pct_wfh) |> head(5)
WarningPrinting a request or a response prints your key

If you print(wfh_request) or print(wfh_response) in a document you knit and push, your key goes with it.

  • Don’t print the request or the response in your final document
  • Never type the key into your code: use Sys.getenv("CENSUS_API_KEY")
  • If you slip up, get a new key and ask for help removing the old one from your repo
